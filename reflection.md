# Reflection

Using Supabase with PostgresSaver provides persistent conversation memory, unlike InMemorySaver, which loses all conversation data when the runtime is restarted. However, this approach requires additional database configuration, secure management of credentials, and may introduce additional latency due to database communication. In the Supabase Table Editor, I observed the checkpoint tables used by LangGraph to store conversation states. After restarting the Colab runtime, I successfully restored previous conversations, including their messages and selected topics. During my off-topic tests, the chatbot correctly refused all unrelated questions, so no changes to the original SystemMessage were necessary. Although the conversation history was successfully preserved, I did not specifically test whether previous messages could influence the chatbot after switching to a different topic.
